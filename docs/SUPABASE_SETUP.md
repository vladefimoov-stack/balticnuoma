# Подключение базы данных Supabase — пошаговая инструкция

Займёт ~15 минут. Командная строка **не нужна** — всё делается в браузере.

**Что такое Supabase:** облачная база данных сайта. В ней хранятся автомобили, фото, брони и
настройки, через неё же будет вход в админку.

**Понадобится:** аккаунт GitHub (или email) и доступ к проекту `balticnuoma` в Vercel.

> Если какой-то пункт в интерфейсе называется немного иначе — ищите по смыслу: Supabase и Vercel
> иногда переименовывают кнопки. Если застряли — пришлите скриншот или текст ошибки.

---

## Шаг 1. Регистрация в Supabase

1. Откройте https://supabase.com и нажмите **Start your project** (или **Sign in**).
2. Выберите **Continue with GitHub** — удобнее всего, раз репозиторий уже на GitHub.
   Подтвердите доступ.
3. Если Supabase попросит создать **организацию** (Organization): имя — `Baltic Nuoma`,
   тип — _Company_ или _Personal_ (не важно), план — **Free**. Нажмите **Create organization**.

## Шаг 2. Создание проекта

1. Нажмите **New project**.
2. Заполните форму:

   | Поле                  | Что указать                                                                                                  |
   | --------------------- | ------------------------------------------------------------------------------------------------------------ |
   | **Organization**      | `Baltic Nuoma`                                                                                               |
   | **Project name**      | `balticnuoma`                                                                                                |
   | **Database password** | нажмите **Generate a password**, затем **скопируйте и сохраните** пароль (например, в менеджер паролей)      |
   | **Region**            | **Central EU (Frankfurt)** — ближе всего к Литве и к серверам сайта на Vercel. Если выбор общий — **Europe** |
   | **Compute size**      | оставьте по умолчанию (на Free — минимальный)                                                                |

3. Если есть блок **Security options** / **Advanced configuration** — **оставьте значения по
   умолчанию**: _Data API + Connection String_ и _Use public schema for Data API_.
   Сайт работает именно через Data API и схему `public`.
4. Нажмите **Create new project** и подождите 1–2 минуты, пока проект создаётся
   (вверху будет надпись «Setting up project»).

## Шаг 3. Создание таблиц и стартовых данных (один SQL-файл)

Все таблицы, правила доступа, хранилища фото и стартовые данные (5 Toyota Prius, категории,
тарифы, справочник марок) собраны в один файл.

1. Откройте файл на GitHub:
   https://github.com/vladefimoov-stack/balticnuoma/blob/main/supabase/production-setup.sql
2. Справа над текстом файла нажмите кнопку **Copy raw file** (иконка «два квадратика»).
   Весь файл (~1000 строк) скопируется в буфер обмена.
3. В Supabase в левом меню откройте **SQL Editor** (иконка `>_`).
4. Нажмите **+ New query** (или **New SQL snippet**). Откроется пустое поле.
5. Вставьте скопированное: щёлкните в поле, затем `Ctrl + V` (на Mac — `Cmd + V`).
6. Нажмите зелёную кнопку **Run** справа внизу (или `Ctrl + Enter`).
7. Supabase может показать предупреждение **«Potential issue detected… destructive operation»** —
   это нормально (в скрипте есть команды, ограничивающие права посетителей). Нажмите
   **Run this query**.
8. Через несколько секунд внизу появится **«Success. No rows returned»** — готово.

**Если появилась ошибка:**

- `Baltic Nuoma database is already installed` — база уже установлена (скрипт запускали
  раньше). Всё в порядке, ничего делать не нужно.
- любая другая ошибка — скопируйте её текст и пришлите мне. Скрипт работает «всё или ничего»:
  при ошибке в базе ничего не меняется, его можно спокойно запустить ещё раз после исправления.

## Шаг 4. Проверка

1. В левом меню откройте **Table Editor**.
2. Слева появится список таблиц: `bookings`, `cars`, `categories`, `makes`, `settings` и другие.
3. Откройте `cars` — там должно быть **6 строк**: `Toyota Prius #1 … #5` (статус `published`)
   и `Porsche Panamera 4 E-Hybrid` (статус `draft` — демо-карточка люкс-класса, на сайте не видна).

## Шаг 5. Закрыть регистрацию и указать адрес сайта

Пользователей админки (вас и менеджера) создаём мы сами, поэтому регистрация «с улицы»
должна быть выключена.

1. Левое меню → **Authentication** → **Sign In / Providers** (в некоторых версиях —
   **Providers** или **Settings**).
2. Найдите переключатель **Allow new users to sign up** и **выключите** его.
   Нажмите **Save changes**.
3. Там же, в разделе **Authentication**, откройте **URL Configuration**.
4. В поле **Site URL** укажите `https://balticnuoma.vercel.app` (позже заменим на ваш домен).
   Нажмите **Save changes**.

## Шаг 6. Скопировать три значения для сайта

Сайту нужны адрес проекта и два ключа. Откройте их в соседней вкладке — понадобятся на шаге 7.

1. **Адрес проекта (Project URL).** Левое меню → **Project Settings** (шестерёнка внизу) →
   **Data API** (или кнопка **Connect** вверху страницы). Скопируйте **Project URL** — вида
   `https://abcdefghijklmnop.supabase.co`.
2. **Публичный ключ (Publishable key).** **Project Settings** → **API Keys**. Скопируйте
   **Publishable key** — начинается с `sb_publishable_…`. Этот ключ не секретный: он и так виден
   в коде сайта, его можно присылать мне.
3. **Секретный ключ (Secret key).** На той же странице, блок **Secret keys** → нажмите на
   ключ, чтобы показать его, и скопируйте — начинается с `sb_secret_…`.
   ⚠️ Этот ключ даёт **полный доступ** к базе в обход всех ограничений. Вставляйте его
   **только в Vercel** (шаг 7). Не отправляйте его в чат, мессенджеры и почту.

> Если вместо Publishable / Secret вы видите вкладку **Legacy API Keys** с ключами `anon` и
> `service_role` — они тоже подходят: `anon` вместо Publishable, `service_role` вместо Secret.

## Шаг 7. Добавить значения в Vercel

1. Откройте https://vercel.com → проект **balticnuoma** → вкладка **Settings** →
   слева **Environment Variables**.
2. Добавьте 4 переменные. Для каждой: впишите **Key** и **Value**, в **Environments** отметьте
   **Production**, **Preview** и **Development**, нажмите **Save**:

   | Key (имя — копируйте точно)     | Value (значение)                            |
   | ------------------------------- | ------------------------------------------- |
   | `NEXT_PUBLIC_SUPABASE_URL`      | Project URL из шага 6.1                     |
   | `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Publishable key (`sb_publishable_…`) из 6.2 |
   | `SUPABASE_SERVICE_ROLE_KEY`     | Secret key (`sb_secret_…`) из 6.3           |
   | `NEXT_PUBLIC_SITE_URL`          | `https://balticnuoma.vercel.app`            |

   Для `SUPABASE_SERVICE_ROLE_KEY` включите переключатель **Sensitive**, если он есть — тогда
   значение больше никто не увидит в интерфейсе.

3. Новые значения применяются только при новой сборке. Откройте вкладку **Deployments** →
   у самой верхней сборки нажмите **⋯** (три точки) → **Redeploy** → **Redeploy**.
   Сборка займёт ~1–2 минуты.

Внешне сайт пока не изменится: машины из базы начнут показываться в фазе 3.

## Шаг 8. Сообщите мне

Напишите, что готово, и пришлите **Project URL** и **Publishable key** (они не секретные).
Я проверю, что база отвечает и сайт её видит. Секретный ключ не присылайте.

## Что ещё полезно знать

- **Пароль базы данных** из шага 2 сейчас не нужен, но сохраните его — пригодится для
  резервных копий и переноса данных.
- **Бесплатный план (Free)** подходит для запуска. Учтите: если к базе никто не обращается
  7 дней, Supabase ставит проект на паузу (данные сохраняются, включается одной кнопкой в
  панели). Перед активной рекламой стоит перейти на **Pro** (~25 $/мес): без пауз и с
  ежедневными резервными копиями.
- **Вход в админку** (ваш логин и пароль) создадим в фазе 6, когда будет готова сама админка.
- **Изменения базы в будущем** (новые таблицы и поля) я буду присылать отдельными небольшими
  SQL-файлами с такой же инструкцией — или применять сам, если дадите доступ.
